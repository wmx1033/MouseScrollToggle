# 辅助功能权限

Swift 核心使用 AXIsProcessTrustedWithOptions 检查权限。未授权时必须失败并提示：

> 启动失败：未获得辅助功能权限。请打开：系统设置 → 隐私与安全性 → 辅助功能。

首次授权需要用户手动完成，再执行快捷指令。具体授权条目须通过真实启动链验证后在发行说明中记录，不能预先保证某一宿主条目即可生效。

稳定可执行路径并避免重复编译；替换二进制、重新编译或改变签名可能需要重新授权。授权撤销必须反映为错误状态。禁止绕过权限、修改 SIP 或整体使用 root。本轮授权后已验证当前路径的服务健康；具体设置条目尚待用户核对。

Phase 2 已通过临时 HOME/独立服务名真实 bootstrap 验证未授权启动：start 返回 1，status 为 ERROR；未出现 RUNNING。请授权稳定路径二进制后重新 start。更新旧服务若失去授权会回滚并如实报告恢复是否成功。

Phase 3 的快捷指令宿主还可能要求“快捷指令 → 设置 → 高级 → 允许运行脚本”；这是用户手动开启的脚本执行许可，不替代辅助功能。实际快捷指令宿主授权条目尚未验证。每台 Mac 独立授权；iCloud 不同步权限。载荷本机编译后仍用稳定路径，新核心更新可能重新触发授权。

Phase 4 实测出现过“当前终端 --check-permission 已授权，但首次 launchctl 启动仍返回2”的上下文差异。用户配合授权后，后续服务实际进入 RUNNING 并通过 Tap 挑战；不能用终端权限探测替代服务健康。doctor 只使用不弹窗的 --check-permission，不创建 Tap。快捷指令宿主条目仍须在实际应用内验收；权限撤销只由用户操作，之后先查询 doctor/status，再由用户恢复授权。

本轮用户报告操作条目为 mousescrolltoggle，并在测试后恢复。仅关闭该条目后，当前控制入口启动失败，但从 shortcuts run 仍能启动健康Tap；当前终端 --check-permission 也可能仍为AUTHORIZED。这些结果提示不能用一个条目推断整条授权链；责任宿主或系统授权缓存可能相关，但本轮未定位根因。完整授权链及运行中撤销仍需另行验收，不建议为测试而批量关闭其他应用权限。
