# MouseScrollToggle — macOS 鼠标滚轮反转工具开发计划

**项目版本：** v1.0 规划  
**开发语言：** Swift + Zsh  
**目标平台：** macOS（Apple Silicon / Intel）  
**部署方式：** macOS Shortcuts + iCloud 同步  
**授权方式：** macOS 辅助功能权限  
**原则：** 极简、轻量、可维护、无自动开机启动

---

## 一、项目背景与目标

### 1.1 问题描述

macOS 默认将鼠标滚轮和触摸板的自然滚动设置关联在一起。

用户希望：

- MacBook 触摸板继续使用自然滚动。
- 外接普通鼠标使用 Windows/Linux 习惯的滚动方向。
- 不修改系统的全局自然滚动设置。
- 可以通过 macOS 快捷指令手动开启和关闭。
- 快捷指令通过 iCloud 同步到不同 Mac。
- 每台 Mac 独立安装、运行和管理。
- 尽量不依赖外部应用或第三方包。

### 1.2 核心功能

| 编号 | 功能 | 优先级 |
|---|---|---|
| F01 | 反转普通鼠标垂直滚轮 | P0 |
| F02 | 保持触摸板滚动方向不变 | P0 |
| F03 | 单个快捷指令切换开启/关闭 | P0 |
| F04 | 首次运行自动安装 | P0 |
| F05 | 状态检测与错误提示 | P0 |
| F06 | 支持 Apple Silicon / Intel | P0 |
| F07 | 通过 iCloud 同步快捷指令 | P0 |
| F08 | 无开机自启 | P0 |
| F09 | 版本检测及按需升级 | P1 |
| F10 | 完整卸载及清理 | P1 |
| F11 | 调试日志与设备兼容性诊断 | P1 |
| F12 | 水平滚动独立控制 | P2 |

### 1.3 非目标

v1.0 不要求：

- 实现完整 GUI 应用。
- 创建系统菜单栏常驻图标。
- 支持 Apple Magic Mouse 的精确识别。
- 提供复杂的鼠标按键映射。
- 调整鼠标指针加速度。
- 对特殊游戏或直接读取 HID 的软件提供保证。
- 自动开机启动。
- 绕过 macOS 的系统权限限制。

## 二、总体架构

采用三个逻辑层：

```text
┌─────────────────────────────────────┐
│     macOS Shortcuts + iCloud        │
│                                     │
│  一键切换 / 首次安装 / 版本管理      │
└──────────────────┬──────────────────┘
                   │
                   ▼
┌─────────────────────────────────────┐
│         Zsh 控制脚本                │
│                                     │
│   install / start / stop / status   │
│   upgrade / uninstall / doctor      │
└──────────────────┬──────────────────┘
                   │
                   ▼
┌─────────────────────────────────────┐
│         Swift 后台程序              │
│                                     │
│   CGEventTap + Scroll Classifier    │
│          + Delta Modifier           │
└──────────────────┬──────────────────┘
                   │
                   ▼
        macOS 滚动事件处理
```

### 2.1 Swift 核心模块

使用系统自带框架：

- Foundation
- CoreGraphics
- ApplicationServices

使用 `CGEventTapCreate` 创建事件监听器，监听 `scrollWheel` 事件。

基本流程：

1. macOS 产生滚动事件。
2. 事件进入 CGEventTap 回调。
3. 读取 `scrollWheelEventIsContinuous`。
4. 判断是否属于需要反转的滚动事件。
5. 修改滚动增量。
6. 返回原事件供系统继续处理。

禁止使用高频轮询、屏幕刷新循环或主动模拟滚动作为正常工作机制。

### 2.2 输入设备识别策略

v1.0 使用事件类型识别，不实现完整物理设备识别。

分类规则：

| 条件 | 分类 | 行为 |
|---|---|---|
| `isContinuous == 0` | 普通机械滚轮 | 反转 |
| `isContinuous != 0` | 触摸板或平滑滚动设备 | 原样放行 |
| 类型无法可靠判断 | 未知 | 原样放行 |

要求：

- 不可以假设所有鼠标都产生离散事件。
- 不可以为了兼容某个鼠标而默认反转全部连续事件。
- 未知情况优先保证触摸板行为不受破坏。
- Debug 模式必须输出实际分类结果。

后续如果需要支持更多设备，可以考虑 HID 来源识别，但不能影响 v1.0 的简洁性。

## 三、滚动事件处理模块

### 3.1 事件字段

需要正确处理以下字段：

```swift
.scrollWheelEventDeltaAxis1
.scrollWheelEventDeltaAxis2

.scrollWheelEventFixedPtDeltaAxis1
.scrollWheelEventFixedPtDeltaAxis2

.scrollWheelEventPointDeltaAxis1
.scrollWheelEventPointDeltaAxis2
```

对于需要反转的滚动事件：

- 默认反转垂直方向 Axis1。
- v1.0 默认保留水平方向 Axis2。
- 必须保持三种垂直增量表达的一致性。
- 保留事件的其他元数据。
- 不改变触摸板惯性及滚动阶段。
- 不额外生成重复滚动事件。

对于 Fixed Point 字段，必须理解其数值格式，避免按整数错误处理。

测试负数极值，防止取负时发生整数溢出。

### 3.2 Event Tap 生命周期

程序必须能够：

1. 创建事件监听器。
2. 将监听器加入当前 RunLoop。
3. 正常运行并等待滚动事件。
4. 处理系统禁用事件监听器的情况。
5. 收到退出信号时释放资源。

需要处理：

```swift
.tapDisabledByTimeout
.tapDisabledByUserInput
```

可以尝试使用 `CGEvent.tapEnable()` 恢复监听，但必须设置重试限制，避免陷入无限重试。

### 3.3 权限管理

使用：

```swift
AXIsProcessTrustedWithOptions(...)
```

检查辅助功能权限。

如果没有授权：

- 输出明确的错误信息。
- 引导用户打开系统设置。
- 不假装程序已经正常工作。
- 不尝试绕过系统权限。
- 授权后允许用户重试。

**注意：重新编译、替换可执行文件或改变签名可能导致权限需要重新授权。**

必须优先保持稳定的可执行路径，避免无意义的重复编译。

## 四、快捷指令设计

### 4.1 核心原则

只创建一个主要快捷指令：

**Mouse Scroll Toggle**

通过 iCloud 同步到所有 Mac。

快捷指令内包含必要的源码和安装控制逻辑，不要求每台 Mac 克隆 Git 仓库。

用户日常只需要点击一次。

### 4.2 快捷指令运行流程

```text
用户点击快捷指令
          │
          ▼
检查本地安装状态
          │
     ┌────┴─────┐
     │          │
   未安装      已安装
     │          │
     ▼          ▼
写入源码     检查版本
     │          │
编译程序      │
     │          │
生成配置      │
     │          │
     └────┬─────┘
          │
          ▼
     检查运行状态
          │
    ┌─────┴──────┐
    │            │
  已运行        未运行
    │            │
    ▼            ▼
 停止服务      启动服务
    │            │
    └─────┬──────┘
          │
          ▼
    验证实际状态
          │
          ▼
    输出操作结果
```

重要约束：首次安装不应因为尚未运行就先启动再立即停止。

### 4.3 首次安装

首次运行时：

1. 检查 macOS 系统和 CPU 架构。
2. 检查 `swiftc` 是否存在。
3. 缺少 Swift 编译环境时提示安装 Xcode Command Line Tools。
4. 将 Swift 源码写入本地工作目录。
5. 编译生成可执行程序。
6. 创建进程管理配置。
7. 检查辅助功能权限。
8. 加载服务并验证启动。
9. 告知用户当前状态。

首次授权仍然需要用户在系统设置中手动完成。

不允许以 `sudo` 运行整个安装过程。

### 4.4 后续操作

如果已经安装：

- 检查后台服务。
- 正在运行则停止。
- 没有运行则启动。
- 验证执行结果。
- 返回中文状态信息。

预期交互：

```text
首次点击：
鼠标滚轮反转：已开启

再次点击：
鼠标滚轮反转：已关闭

再次点击：
鼠标滚轮反转：已开启
```

发生异常时：

```text
启动失败：未获得辅助功能权限

请打开：
系统设置 → 隐私与安全性 → 辅助功能
```

不得只依靠脚本退出码判断 Event Tap 是否真正可用。

## 五、后台进程管理

### 5.1 选择 launchctl

使用用户会话内的 `launchctl` 服务管理 Swift 程序。

推荐服务名称：

```text
local.mousescrolltoggle
```

服务配置放在：

```text
~/.config/mousescrolltoggle/agent.plist
```

不要复制到：

```text
~/Library/LaunchAgents/
```

这样可以避免系统登录时自动扫描并加载该服务。

使用以下操作管理：

```bash
launchctl bootstrap
launchctl bootout
launchctl print
launchctl kickstart
```

必须为这些命令指定正确的 `gui/<uid>` 服务域。

### 5.2 运行生命周期要求

- 用户手动开启时加载。
- 用户手动关闭时卸载。
- macOS 用户退出登录后不保持运行。
- 重新登录后不自动启动。
- 允许当前用户会话内的进程异常恢复。
- 不能启动重复实例。

可以采用 `KeepAlive=true`，但只在用户已经手动加载服务的期间生效。

需要测试服务退出、重启、重复点击和系统休眠后的行为。

### 5.3 状态管理

最少区分四种状态：

```text
NOT_INSTALLED
STOPPED
RUNNING
ERROR
```

运行状态不能仅通过可执行文件是否存在判断。

需要结合：

- launchctl 服务是否加载。
- 服务是否处于运行状态。
- Swift 核心程序的健康状态。
- Event Tap 是否创建成功。

如果服务存在但 Event Tap 无法工作，应当报告错误，而不是显示“已开启”。

## 七、iCloud 同步设计

### 7.1 同步内容

通过 macOS 快捷指令同步：

- 快捷指令操作流程。
- 安装和启动控制脚本。
- Swift 源代码或其内嵌构建载荷。
- 项目版本号。

### 7.2 不同步内容

以下内容由每台 Mac 自己生成：

- 编译完成的可执行文件。
- 当前运行状态。
- launchctl 服务。
- 权限授权记录。
- 本地日志。
- 编译缓存。

不同 CPU 架构的 Mac 应当独立编译。

### 7.3 版本管理

推荐在快捷指令中嵌入：

```text
APP_VERSION=1.0.0
```

本地保存已安装版本及源码哈希。

每次运行：

1. 计算快捷指令携带的源码哈希。
2. 与已安装版本比较。
3. 内容相同则跳过编译。
4. 内容不同才执行升级。
5. 升级成功后更新版本记录。

升级过程必须支持失败回滚。

为避免辅助功能授权频繁失效，不要每次点击都重新编译，也不要仅为更新版本文本就替换核心二进制。

### 7.4 自包含快捷指令生成

开发 Agent 应负责生成完整的 `shortcut-payload.sh`。

该文件需要：

- 包含 Swift 源码。
- 包含安装逻辑。
- 包含启停逻辑。
- 不依赖 GitHub 下载。
- 不依赖 Homebrew。
- 不包含机器特定的绝对路径。
- 支持路径中出现空格。
- 不需要管理员权限。

如果系统支持可靠的快捷指令导入或生成方式，可进一步生成可导入的 `.shortcut` 文件。

如果无法可靠地自动生成，应提供图文或文字导入步骤，不得宣称已经创建成功。

## 八、性能与稳定性

### 8.1 性能目标

| 指标 | 目标 |
|---|---|
| 空闲 CPU 占用 | 接近 0% |
| 常驻内存 | 尽量低，建议 10 MB 以内 |
| 空闲时轮询 | 无 |
| 后台网络访问 | 无 |
| 滚动额外延迟 | 无明显可感知延迟 |
| 重复开启 | 不产生额外进程 |
| 停止服务 | 及时恢复原始滚动 |
| 权限异常 | 明确提示 |

内存和 CPU 指标以实际设备测量为准，不硬编码未经测试的性能承诺。

### 8.2 稳定性要求

测试以下情况：

- Mac 休眠后唤醒。
- 蓝牙鼠标断开后重新连接。
- 2.4G 接收器拔出后重新插入。
- USB 鼠标热插拔。
- 触摸板与鼠标交替滚动。
- 鼠标快速连续滚动。
- 多桌面与全屏应用切换。
- 退出登录后重新登录。
- 快捷指令连续快速点击。
- 编译失败。
- 辅助功能权限被撤销。
- Event Tap 被 macOS 禁用。

不能出现滚动事件无限循环、双倍滚动或持续丢失滚动事件。

## 十二、给开发 Agent 的执行要求

1. 优先实现一个简单、正确、稳定的版本，不要过度工程化。
2. 优先使用 Apple 官方公开 API。
3. 不使用未经必要性验证的私有系统 API。
4. 不使用第三方 Swift 软件包。
5. 不引入 Homebrew 作为运行依赖。
6. 不修改系统全局自然滚动设置。
7. 不修改 SIP 或其他系统安全机制。
8. 不需要 root 权限。
9. 安装脚本需要具备幂等性。
10. 升级过程必须考虑权限授权稳定性。
11. 不允许无提示覆盖用户已有配置。
12. 所有 Shell 脚本使用合理的错误检测及退出码。
13. 任何编译或安装失败都应输出具体原因。
14. 代码实现完成后必须尝试编译、运行自动化测试并记录结果。
15. 如果无法进行真实鼠标测试，必须在报告中明确标注“未验证”，不能宣称通过。
16. 对无法通过 CLI 自动完成的快捷指令导入或权限授权，提供清晰的人工操作说明。

- [ ] MacBook 触摸板方向不受影响。
- [ ] 触摸板惯性滚动正常。
- [ ] 快捷指令可以开启、关闭程序。
