# 测试

`make test` 保留 35 项 Swift 合成事件/恢复预算检查。`make integration-test` 执行 87 项扩展隔离检查：临时 HOME（包含空格与 &）、仓库副本、mock launchctl/core，不修改真实安装。覆盖安装幂等、版本变化、配置冲突、编译失败、回滚及旧服务恢复失败报告、启停幂等、首次 toggle、并发 start、暂停核心及陈旧响应、运行中卸载、重复卸载、未知文件保护与无 LaunchAgents。

模拟通过不证明真实 launchctl 或 Tap 行为。真实测试与人工步骤见 docs/test-report.md。

Review 回归新增完整恢复失败矩阵及恢复脚本实执行、前台锁占用阻止操作、陈旧 PID 不发信号与真实核心返回 5。真实核心锁检查与模拟 launchctl 测试分开解释，详见测试报告。

`make shortcut-test` 的 64 项检查使用共享 mock-runtime.sh 适配器覆盖确定性生成、一致性、Shell 语法、离仓库执行、特殊字符路径、首次点击、连续点击、版本/核心/脚本更新、编译/启动失败、跨临时目录恢复、未完成事务、旧版本拒绝及整次点击并发。明确使用临时 HOME、独立服务名；不证明 UI/iCloud 或硬件验收。`make check-shortcut` 逐字节检查生成产物是否过期。

Phase 4：`make diagnostic-test` 覆盖缺失二进制/工具链、未运行/健康/不健康/异常退出、脱敏、未完成事务、载荷诊断、10秒锁超时、路径阻塞/只读安装目录、配置符号链接。普通套件都使用隔离 HOME 和显式适配器。共享 test-support.sh 在退出/INT/TERM 清理本轮子进程，对 mock 服务验证启动时间和命令路径再清理；mock 本身也有3600次×50ms的有限等待预算（另含调度开销）。就绪等待均有上限。

`Tests/system-tests.sh --live` 是**明确手动选择的真实验收入口**，不在普通 make test 中执行。仅在稳定安装已授权、当前服务未加载、用户安排测试窗口后运行；会真实启停、发信号、注入本项目日志大小，最后保持停止。已有加载服务时拒绝，清理失败会明确提示。该入口本身不安装或弹出权限申请；测试未托管实例时调用安装/卸载入口，预期全部拒绝，不能在未知版本上盲跑。不要与使用中的快捷指令并行运行。证据索引见 docs/phase4-evidence.md，原始调试事件不入库，只保留计数、简洁结果与性能 CSV。

`make cleanup-test` 实际验证测试框架自身的失败与SIGTERM中断路径：退出码、孤立mock核心被清理、临时目录被删除，共6项，避免只声明已写trap而不验证清理。系统复测入口的前台信号退出另有约2秒等待上限，超时强制清理并报告失败。
